PROMPT PARA CLAUDE — CONSTRUÇÃO DE PLATAFORMA DE AUTOMAÇÃO PARA INSTAGRAM

Você é o principal desenvolvedor deste projeto. Sua missão é construir uma plataforma web de automação para Instagram, inspirada conceitualmente em ferramentas como ManyChat, mas começando com um MVP enxuto, funcional e bem estruturado.

IMPORTANTE:
- Não quero uma cópia visual ou de código do ManyChat.
- Quero construir nosso próprio sistema.
- O foco inicial é AUTOMOÇÃO + WORKFLOW PARA INSTAGRAM.
- A integração com Instagram deve utilizar exclusivamente as APIs oficiais da Meta.
- NÃO utilize métodos não oficiais, scraping, automação de navegador, bibliotecas que simulem usuário do Instagram ou qualquer técnica que possa causar bloqueio da conta.
- Antes de implementar qualquer integração da Meta, consulte a documentação oficial vigente e confirme quais endpoints, permissões, produtos e tipos de conta são atualmente suportados.
- Não invente endpoints, permissões, campos ou comportamentos da API.
- Se alguma funcionalidade desejada não for oficialmente suportada, informe isso e proponha a alternativa oficial mais próxima.
- O sistema deve ser simples na primeira versão, mas com arquitetura que permita evolução.

==================================================
1. OBJETIVO DO PRODUTO
==================================================

Criar uma plataforma web onde o usuário consiga:

1. Criar uma conta e entrar no painel.
2. Conectar sua conta do Instagram de forma simples e segura através da Meta.
3. Visualizar o status da conexão.
4. Criar workflows/automações.
5. Criar gatilhos.
6. Adicionar condições.
7. Adicionar ações.
8. Organizar visualmente o fluxo.
9. Salvar, editar, duplicar, ativar, desativar e excluir workflows.
10. Executar ações automaticamente quando um gatilho compatível ocorrer.
11. Utilizar IA da OpenAI em determinados pontos do workflow.
12. Visualizar logs das execuções.
13. Configurar dados da integração.
14. Ter uma interface simples e profissional.

A visão futura é transformar isso em uma plataforma muito mais próxima de um ManyChat completo, mas NÃO tente construir tudo agora.

==================================================
2. STACK PRINCIPAL
==================================================

Backend:
- Python
- Flask

Banco:
- Supabase
- PostgreSQL do Supabase

Frontend:
- Escolha uma tecnologia adequada para construir um editor visual de workflows.
- Pode utilizar React + Vite caso seja a opção mais apropriada.
- O frontend deve conversar com o Flask por API.
- Não crie um frontend excessivamente complexo.

Integração:
- Meta Graph API / APIs oficiais do Instagram
- OAuth oficial da Meta
- Webhooks oficiais da Meta

IA:
- OpenAI API

Hospedagem:
- O projeto deve ser preparado para deploy em ambiente Linux/cloud.
- Não assuma que haverá execução local permanente.
- Variáveis sensíveis devem estar em ambiente (.env localmente e secrets no servidor).

==================================================
4. AUTENTICAÇÃO
==================================================

Implemente autenticação segura.

O usuário deve conseguir:

- criar conta
- fazer login
- fazer logout
- manter sessão autenticada
- acessar apenas seus próprios dados

Não misture dados entre usuários.

Utilize mecanismos seguros de autenticação e autorização.

Se usar Supabase Auth, avalie se ele é a melhor opção para o MVP e utilize corretamente os recursos oficiais.

Nunca armazene senha em texto puro.

==================================================
5. CONEXÃO COM INSTAGRAM / META
==================================================

Esta é uma das partes mais importantes do projeto.

A experiência do usuário deve ser aproximadamente:

Configurações
→ Instagram
→ Conectar Instagram
→ Login/autorização da Meta
→ Usuário concede permissões
→ Retorno para a plataforma
→ Sistema valida a conexão
→ Conta aparece como conectada

Interface:

INSTAGRAM
[ Conectar Instagram ]

Depois da conexão:

Instagram conectado
@usuario
Status: Conectado
[Reconectar]
[Desconectar]

REQUISITOS:

- Utilizar OAuth oficial da Meta.
- Utilizar somente permissões realmente necessárias.
- Não solicitar permissões desnecessárias.
- Armazenar tokens de forma segura.
- Não exibir tokens no frontend.
- Implementar tratamento de expiração/renovação conforme o fluxo oficial vigente.
- Validar o vínculo entre usuário da plataforma e conta Instagram.
- Implementar desconexão.
- Implementar tratamento de erros de autorização.
- Registrar informações úteis de diagnóstico sem registrar secrets.

ANTES DE IMPLEMENTAR:

Consulte a documentação oficial atual da Meta e determine:

- requisitos atuais para contas Instagram;
- requisitos de conta profissional, caso aplicável;
- produto/API correto;
- permissões necessárias;
- fluxo OAuth atual;
- endpoints atuais;
- webhooks disponíveis;
- limitações atuais;
- tipos de mensagens/eventos que podem ser recebidos;
- ações que podem ser executadas oficialmente.

Não assuma que recursos antigos da Instagram Basic Display API continuam disponíveis ou adequados para automação.

==================================================
6. WEBHOOKS
==================================================

A plataforma deverá possuir endpoint para receber webhooks oficiais da Meta.

Exemplo conceitual:

POST /webhooks/meta

GET /webhooks/meta

O GET deve permitir a verificação exigida pela Meta.

O POST deve:

1. validar a requisição;
2. identificar o evento;
3. registrar o evento;
4. identificar a conta;
5. encontrar workflows relacionados;
6. encaminhar para o motor de automação;
7. retornar rapidamente uma resposta apropriada.

Não processe operações demoradas diretamente no request do webhook se isso puder causar timeout.

Para operações demoradas, crie uma estrutura de jobs/background processing.

- nome
- descrição opcional
- status
- gatilho
- nós
- conexões
- configurações
- data de criação

Status:

- Ativo
- Inativo

==================================================
9. TIPOS DE NÓ
==================================================

Crie uma arquitetura extensível de nodes.

Categorias:

GATILHOS

Exemplos, somente se suportados pela API oficial vigente:

- nova mensagem recebida;
- evento de mensagem compatível;
- comentário/evento compatível;
- outros eventos oficiais disponíveis.

AÇÕES

Exemplos:

- enviar resposta;
- enviar mensagem;
- adicionar atraso;
- chamar IA;
- definir variável;
- alterar variável;
- executar condição;
- finalizar workflow.

CONDIÇÕES

Exemplos:

- texto contém;
- texto é igual;
- variável existe;
- variável possui valor;
- condição baseada em resposta da IA;
- outros operadores simples.

==================================================
10. MOTOR DE EXECUÇÃO
==================================================

Crie um Workflow Engine.

Ele deve:

1. receber um evento;
2. localizar workflows ativos;
3. verificar o gatilho;
4. iniciar execução;
5. processar os nós na ordem correta;
6. avaliar condições;
7. executar ações;
8. registrar o resultado;
9. continuar ou finalizar o workflow.

Cada execução deve possuir um identificador.

Exemplo:

execution_id
workflow_id
trigger_event
started_at
finished_at
status
error

==================================================
11. FILA / BACKGROUND JOBS
==================================================

Como workflows podem possuir:

- delays;
- chamadas à Meta;
- chamadas à OpenAI;
- múltiplas ações;

não faça tudo de forma síncrona quando isso prejudicar a estabilidade.

Para o MVP, implemente uma solução simples.

Pode utilizar:

- Celery + Redis
OU
- RQ + Redis
OU
- outra solução simples e adequada.

Se a complexidade não for necessária inicialmente, crie uma arquitetura que permita adicionar uma fila posteriormente.

Não introduza infraestrutura desnecessária sem motivo.

==================================================
12. DELAYS
==================================================

O workflow deve permitir futuramente:

Ação:
"Esperar 30 segundos"

Depois:
"Enviar mensagem"

Não use sleep() segurando uma requisição web.

O delay deve ser processado por mecanismo apropriado de jobs.

==================================================

[ IA ]

Configurações possíveis:

- modelo;
- system prompt;
- instruções;
- mensagem/contexto de entrada;
- temperatura, se suportada pelo modelo escolhido;
- formato da resposta;
- variável onde salvar a resposta.

Exemplo:

Mensagem recebida
      ↓
IA
      ↓
Condição
      ↓
Resposta

A IA deve poder receber contexto relevante do workflow.

Não envie dados desnecessários para a OpenAI.

As chaves da OpenAI nunca podem aparecer no frontend.

Use variável:

OPENAI_API_KEY

Não coloque API key diretamente no código.
